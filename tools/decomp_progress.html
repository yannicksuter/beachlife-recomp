Metric definitions, executable ranges and inventory gaps

Matching: the byte lengths of complete game methods with a strict 100% normalized comparison, divided by bounded game-method bytes in this inventory. Partial similarity scores are shown on individual candidates but do not count as completed bytes. Raw byte equality is reported separately.

Linking: bounded game-method bytes integrated into the production native runtime, over the same bounded-game denominator. A method in the small VC6 comparison image or a native test harness does not count as production linkage.

Coverage: known nonoverlapping function bodies divided by the logical executable-section extent. Address-only observations and code fragments add no completed bytes. Libraries, compiler glue and functions of unresolved provenance remain separate from game-method progress. Unclassified functions use the same strict comparison gate, but their matched bytes count toward neither game nor library totals. Section file-alignment tails are excluded; padding inside logical sections remains unclassified until identified.

Source TUs: current reconstructed C++ files, with percentages over their registered methods. They are not recovered original translation units. Subsystems with no audited methods remain “Unmapped”. Original data/global coverage and a whole-game function count remain unknown.

Snapshot: current matching inputs are hash-checked when this page is generated. The source revision and snapshot date above identify the saved view. Regenerate it after new evidence; there is no background update or network request.
